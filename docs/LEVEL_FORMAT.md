# Формат уровней — #8

## Источники и статус

[LEVELS.md](LEVELS.md) — копия предоставленного владельцем документа обучения.
Шесть названий, описания и порядок сохранены в `levels/training-plan.json`.
План сохраняет исходный `status: design` как учебный документ; все шесть
записей теперь ссылаются через campaignLevel на готовые сцены #13.
Переходы первого уровня реализованы в #12. В #11 первая запись получила `campaignLevel: training-1`,
ссылающийся на подобранную сцену в `levels/campaign.json`. Подобраны все шесть сцен и финал; см. [CAMPAIGN.md](CAMPAIGN.md).
Километры, км/с, сутки и примеры значений исходного документа не переводятся
в мировые единицы автоматически. В текущей модели годы заданы D-018;
астрономический масштаб длины и скорости ещё не принят.

`levels/mission-examples.json` содержит пять **примеров контракта** с явными
параметрами на основе исходной сцены. Они показывают формат и проверяются
тестами; не являются сбалансированными или доказанно решаемыми миссиями кампании.
Числа из примеров не становятся правилами для остальных уровней.

`src/levels.js` загружает JSON/объект, проверяет его и возвращает отдельную
глубоко замороженную копию. `createGameFromLevel` создаёт изменяемую симуляцию
из неё. `describeMission` формирует задание из реальных условий данных.
Текущая главная страница продолжает запускать сцену Spike; показ целей и
результатов реализован в #10/#31, Win/Lose — в #9. Первый уровень #11
открывается по `?mission=training-1`; его баланс — [FIRST_LEVEL.md](FIRST_LEVEL.md).
Обучение первого уровня описано в [TUTORIAL.md](TUTORIAL.md), полная кампания — [CAMPAIGN.md](CAMPAIGN.md).

## Верхний уровень

```json
{
  "schemaVersion": 1,
  "id": "training-1",
  "title": "Первое вмешательство",
  "description": "Измените окружение корабля и избегите столкновения.",
  "purpose": "campaign",
  "universe": {},
  "placement": {},
  "mission": {},
  "tutorial": {}
}
```

Пустые объекты выше обозначают разделы и **не являются валидной сценой**.
Полные валидные примеры — в `levels/mission-examples.json`.
`purpose` отличает `campaign` от `contract-example`. Ошибки содержат путь поля.
Неизвестные поля, версии, ссылки и неполные данные отклоняются до Play.

## Вселенная и ящик

`universe` содержит `id`, `physics`, `camera`, `bodies`, `ship`, `tray`, `earthClock`.
Параметры физики и тел совпадают по структуре со `src/scenario.js`. Версия
динамики — `fixed-euler-swept-v1`, часы — фиксированный контракт D-018.
Менять параметры конкретной сцены нужно явно в данных и проверять её полёт;
загрузчик не подбирает массы и не доказывает решаемость.

У каждого исходного тела уникальный `id`, `type`, `label`, мировые `x/y/vx/vy`,
масса `m >= 0`, радиус `r >= 0`, явный `fixed`. Закреплённое тело имеет нулевую
скорость. Корабль имеет уникальный ID, ненулевую скорость и `fixed: false`.
Стартовая скорость корабля и земного наблюдателя должна быть меньше c=1000;
поле часов должно оставаться численно допустимым. Полный полёт проверяется
отдельно, поскольку корректный старт не гарантирует v<c в дальнейшем.

`tray` задаёт только доступные типы `planet`, `giant`, `star`. У каждого —
`m`, `r`, `drawR`, `label`, целое `count >= 0`. Нулевое количество блокирует тип;
отсутствующий тип недоступен. Можно разрешить несколько тел одного типа.
У каждого размещённого экземпляра отдельный ID; перенос/удаление работают
по нему. Reset сохраняет начальную расстановку, восстанавливает скорости
и обнуляет часы. В старой сцене без уровня сохранён прежний ящик по одному
телу каждого типа; это совместимость со Spike, не ограничение кампании.

`placement` обязательно задаёт `shipClearance`, `bodyGap` и непустой список
`regions`. Размещение разрешено в объединении регионов:

- `{"kind":"circle","x":0,"y":0,"radius":100}`;
- `{"kind":"rect","xMin":-100,"xMax":100,"yMin":-100,"yMax":100}`;
- `{"kind":"polygon","vertices":[{"x":0,"y":0},{"x":100,"y":0},{"x":50,"y":100}]}`;
- `{"kind":"all"}` — вся Вселенная, единственная запись в списке; не рисуется.

Полигон имеет не менее трёх конечных вершин, без повторов, самопересечений,
нулевой площади и последовательных коллинеарных рёбер. Выпуклость не требуется;
порядок обхода любой. Замыкание последней вершины на первую неявное.
Рёбра и вершины включены. Геометрия области ограничивает центр размещаемого
тела; ограничения расстояний проверяются отдельно для всех форм, включая all.
Формы добавлены в совместимый контракт schemaVersion=1 по #37.

Границы размещения включены. `shipClearance` — расстояние между центрами,
`bodyGap` добавляется к сумме радиусов размещаемого и существующего тел.
Числа задаются каждым уровнем явно. Существующие тела игрок не редактирует.

## Цель и скорость

Цель — круг в двумерном мире, сравниваемый с **центром корабля**, без добавления
радиуса корабля к радиусу цели. Данные задают `target.radius > 0` и `target.centre`:

- `{"kind":"fixed","x":500,"y":0}` — неподвижная мировая точка;
- `{"kind":"body","bodyId":"earth","offset":{"x":0,"y":0}}` — центр существующего тела плюс необязательное мировое смещение.

Движение цели читается из действующей физики. Скорость прибытия по документу
владельца — **относительно цели**, `hypot(vShipX-vTargetX, vShipY-vTargetY)`
в мировых единицах / единицу симуляционного времени. Для fixed скорость цели
нулевая; для body берётся скорость тела. Смещение не вращается вместе с телом.
Это разность мировых скоростей игровой модели, не релятивистское сложение скоростей.

`resolveTarget` и `arrivalSpeed` — общие читатели геометрии и скорости.
Они не принимают решения Win/Lose и не определяют, какой проход через цель
считать финальным. Ранний/слишком быстрый проход, касание границы области,
порядок одновременных событий и дробный вход в цель определяются в #9.

## Часы Земли

`earthClock` обязательно задаётся явно:

- `{"kind":"inertial","x":0,"y":0,"vx":0,"vy":0}` — наблюдатель с постоянной мировой скоростью;
- `{"kind":"body","bodyId":"earth","offset":{"x":16,"y":0}}` — наблюдатель, следующий за телом с мировым смещением.

Смещение — место часов, не отдельный источник поля и не вращающаяся поверхность.
При привязке используются положение и обновлённая скорость тела; потенциал
считается в середине фактически пройденного сегмента по всем источникам,
включая собственное поле тела Земли. При столкновении сегмент укорочен.
Обновление Земли, корабля, наблюдателя и двух часов атомарно; ошибка сохраняет
последнее допустимое состояние. Формула и параметры D-018 не меняются.

## Все пять видов миссий

Для любой миссии обязательно `maxCoordinateYears > 0`, конечное число.
Это конечный горизонт попытки в координатных годах, `simulation.time * Y`.
В отличие от собственного срока он обеспечивает ограничение длительности
попытки даже в сильном поле. Применение горизонта в игровом цикле — #9.

1. Выживание: `type: survival`, `survive: {clock: coordinate|earth|ship, years: ...}`.
2. Область: `type: arrival`, `target`, `limits: {}`.
3. Область за собственное время: arrival с `limits.shipYears.max`.
4. Область со временем и скоростью: arrival с `limits.relativeSpeed` и нужными
   `earthYears`/`shipYears`. Скоростное ограничение без дополнительного срока
   также выражается arrival; конечный общий горизонт всё равно обязателен.
5. Возвращение на Землю: `type: earth-return`, цель и земные часы привязаны
   к одному телу; обязательны `limits.earthYears.min`, `shipYears.max` и
   `relativeSpeed.max`. Исторический пример контракта сохраняет 300/100;
   готовый финал #13 использует 500/200 по D-033.

Интервалы имеют одну или обе конечные границы `min/max >= 0`, `min <= max`.
Пустой интервал запрещён. Нижняя граница часов и длительность выживания
не могут превышать координатный горизонт: принятая модель не даёт часам
идти быстрее координатного времени. Требования задания читаются из данных,
без чисел отдельного уровня в общей логике. Временные ограничения выражаются
в игровых годах. `missionClock` явно различает земные, корабельные и координатные годы.

## Обучение

`tutorial` при наличии содержит `showFutureTrajectory: false`,
`showMotionVector: true` и список `steps`. Шаг имеет ID, текст,
`until: collision|success`, `availableCounts` по типам ящика (не выше его лимита).
В этапе доступны только перечисленные типы; пропущенные имеют количество 0.
Первый уровень задаёт сначала планету в количестве 0 до демонстрационного
столкновения, затем 1. Исполнение #12 включает ограничения ящика и API
размещения. Только явный Reset после Lose/collision продвигает аварийный
этап; success требует Win. Отсутствие нужного результата, ошибка и прерванный
полёт не пропускают этап. Сброс сохраняет расстановку и прогресс в этой сессии;
перезагрузка начинает с первого шага. Загрузчик только валидирует данные.

В `training-plan.json` сохранены все шесть названий и цели обучения. Ссылки
`missionExample` показывают примеры соответствующих условий, а не готовые
параметры этих уровней. Необязательный `campaignLevel` связывает запись
с готовыми данными кампании; `loadTrainingPlan(input, examples, campaign)`
проверяет эту ссылку. Статус design относится к обучению и не подменяется
готовностью одной сцены. `deadlineClock` для уровней 4–6 равен ship: владелец выбрал собственные
часы корабля. Формат также умеет земные часы для других заданий.

## Применение в #9

`createGameFromLevel` включает миссию в симуляцию; Reset восстанавливает тот
же контракт. Win/Lose и дробные события реализованы в `src/missions.js`,
правила — [MISSIONS.md](MISSIONS.md), выбор владельца — D-025.
Примеры встраиваются в standalone HTML и открываются через ?mission=<id>.
JSON читается из того же дерева источников, что и JavaScript, включая сборку
из тега; внешние загрузки не нужны. Параметры примеров остаются тестовыми.
