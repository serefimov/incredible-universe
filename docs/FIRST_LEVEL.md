# Первое вмешательство — баланс и проверка #11

Сцена: `levels/campaign.json`, id `training-1`, purpose `campaign`.
Это первый подобранный уровень; контрактные примеры и свободная сцена сохранены.

## Условия и числа сцены

- Цель: выжить **500 лет по часам корабля** без столкновения; горизонт попытки — 700 лет модели.
- Звезда Гелиос: `(70, 0)`, масса 60, радиус 28, закреплена.
- Корабль: `(-150, 0)`, скорость `(35, 0)`, радиус 4.
- Ящик: ровно одна планета, масса 40, радиус 12, начальная скорость 0.
- Размещение: `x ∈ [-150, -20]`, `y ∈ [-150, -50]` или `[50, 150]`; границы включены. Отступ от корабля 45, дополнительный зазор тел 12.
- G=7200, softening=16, фиксированный шаг 0.0025; формулы динамики и часов, c=1000, 100 лет на единицу времени сохранены. Эти массы/координаты — баланс сцены, не глобальные изменения.
- timeScale=0.5: контрольная авария видна примерно за 6 секунд, победный полёт — за 10 секунд активного воспроизведения. Фоновая вкладка не догоняет время.

## Контрольные полёты

Без планеты: Lose, причина collision, тело helios. Время модели
`3.05325427874563`, часы корабля `303.57747671199246` лет; контакт в `(38, 0)`.

Ровно одна планета в `(-110, -120)`: Win, причина survived, часы корабля 500 лет,
время модели `5.038364986424853`. Зеркальное решение `(-110, 120)` даёт тот же
результат. В измерении по кадрам 0.01 секунды минимальный зазор между
поверхностями корабля и любого тела контрольного решения — около 54.38 мир. ед.

Все **234** положения на сетке с шагом 5:
`x ∈ [-140, -80]`, `y ∈ [-140, -100]` и зеркально `[100, 140]`
дают Win. Минимальный измеренный зазор на этой сетке — около 11.40 мир. ед.
Сетка включает края и внутренние положения: это эмпирическая проверка,
не математическое доказательство для каждой вещественной точки.
При стартовом zoom=0.65 проверенная область занимает 39×26 CSS px с каждой
стороны курса, поэтому решение не требует одного точного пикселя.
При изменении параметров сцены эти измерения нужно пересчитать.

`node --test tests/first-level.test.mjs` воспроизводит контроль, сетку,
30/60/120 Hz и смешанное расписание кадров, Win → Reset → перенос → Win →
Reset → удаление → Lose → Reset → размещение → Win. Начальные условия,
загруженные данные и состояния камеры/полёта разделены.

## Данные для #12

`tutorial.steps` содержит observe-collision (planet:0, until:collision) и
intervene (planet:1, until:success). В плане design добавлена ссылка
`campaignLevel: training-1`. Переключение этапов и блокировка выдачи планеты
до аварии не реализованы в #11. Для проверки сцена сразу даёт одну планету;
контрольная попытка выполняется без её размещения. Полная будущая траектория
не показывается, только короткий начальный вектор и след пройденного полёта.

## Проверка на телефоне

Открыть dev-сборку с `?mission=training-1` или ссылку через i свободной сцены.
Сначала запустить без планеты и увидеть столкновение с Гелиосом.
Затем Сброс, разместить планету в верхней отмеченной области чуть впереди
корабля (ориентир контрольного решения выше), запустить и получить Победу.
Сброс должен сохранить планету; передвинуть её немного, повторить попытку,
потом вернуть в ящик. Проверить портрет и альбом, читаемость задания через i,
часы корабля и отсутствие Земли. Браузерная эмуляция не заменяет эту приёмку.
