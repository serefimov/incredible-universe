# Запускаемая основа — #2

Новая игра находится в корневом `index.html` и `src/`. Исходный
`prototypes/spike_0_3.html` сохраняется без изменений. Это перенос игрового
цикла, а не завершённый MVP: миссий, Win и двух времён ещё нет.

## Запуск и сборка

Нужен Node.js 20 или новее:

```sh
npm ci
npm run dev
npm run check
npm run build
```

Локальный адрес — `http://127.0.0.1:8000/`; переменные `HOST` и `PORT` меняют
адрес сервера. Для смартфона в той же сети: `HOST=0.0.0.0 npm run dev` и
`http://<адрес-компьютера>:8000/`. Сервер — только для разработки, без HMR.

`dist/game/index.html` — один HTML со встроенными CSS и скриптом; исходники,
node_modules и сервер ему не нужны. Дополнительный HTML прототипа в сборку
не подмешивается. Запуск модульных исходников требует HTTP-сервера.

## Разделение ответственности

| Часть | Содержимое | Кто меняет |
| --- | --- | --- |
| `scenario` / `src/scenario.js` | Замороженные параметры Spike, начальные тела, корабль, ящик, стартовая камера | Только новая версия сценария в исходниках |
| `configuration` / `src/state.js` | Типы и начальные координаты размещённых игроком тел | Подтверждённое размещение, перенос или удаление |
| `simulation` / `src/physics.js` | Координаты, скорости, время, след, статус и тело столкновения | Шаг физики; Reset создаёт состояние заново |
| `camera` / `src/camera.js` | Центр, масштаб и слежение | Pan, zoom, кнопка корабля и слежение при полёте |
| Ввод / `src/input.js` | Указатели, перенос, pan, pinch; координаты предпросмотра | Pointer Events; Play и Reset очищают жесты |
| Отрисовка / `src/render.js` | Canvas, размер области и визуализация состояния | Читает физику и конфигурацию, не записывает в них |
| Связь с DOM / `src/main.js` | Кнопки, подсказка, карточки и вызовы физики/отрисовки | Действия пользователя и кадровый цикл |

Сценарий не разделяет изменяемые тела с симуляцией. Reset восстанавливает
мир из сценария и расстановки, сбрасывает время/след/столкновение и сохраняет
координаты/масштаб камеры. Добавленные тела снова получают нулевую скорость.
Координаты предпросмотра никогда не записываются в тела полёта.

## Сравнение со Spike

Сохранены начальная сцена, все массы/радиусы/скорости, G и смягчение,
интегратор, порядок обновления, ограничение длительности кадра, остаточный
подшаг, выборка следа, строгое сравнение радиусов при столкновении, один
экземпляр каждого типа ящика, области допустимого размещения и следование
камеры. Полёт начинается после Play, редактирование блокируется в полёте.
Как в Spike, редактирование доступно после столкновения и сбрасывает опыт
при подтверждении правки.

Контрольные тесты исполняют **сам исходный скрипт** в VM, не переписывая HTML.
На одинаковой последовательности подшагов корабль, тела, след и время
совпадают точно в одном JS runtime, для базовой сцены и сцены с планетой.
Нерегулярные кадры сравниваются отдельно вплоть до остановки при столкновении.

Отличия, необходимые для поддерживаемой основы:

- Заголовок новой игры — The Incredible Universe; исторический HTML сохраняет
  прежнее название.
- Предпросмотр переноса отделён от физического состояния. При отмене жеста
  он отбрасывается; отмена над ящиком больше не удаляет тело.
- Play/Reset очищают ввод, hover не регистрируется как нажатый указатель,
  второй палец отменяет перенос перед pinch. Это устраняет утечки состояния,
  но не завершает отдельную задачу удобства touch-first управления #4.
- Canvas пересчитывает размер через ResizeObserver; изменение окна больше
  не оставляет старый размер и ошибочные координаты выбора.
- Готовность запуска определяется явным статусом `ready`, а столкновение
  хранит `collisionId`, чтобы будущие условия миссий читали состояние без DOM.

**Детерминированность пока не исправлена.** Переменный остаток кадра и
проверка столкновения только в конце шага перенесены для сравнения. Тест
явно обнаруживает разные траектории при 60 и 120 Гц. Исправление — #3;
наблюдение владельца о разных повторах в 0.1.0 учитывается как дефект.
Стартовая камера на узком экране ещё может оставлять корабль за кадром;
кнопка «Корабль» центрирует его. Целевые улучшения камеры — #5.

## Проверка

- `npm run check`: аудит неизменённого Spike, проверки состояний, сравнение
  физики, цикл ввода мышью и синтетическими касаниями, сборка и архив выпусков.
- В управляемом браузере на портретном размере проверены размещение,
  Play → столкновение, след, Reset с сохранением тела, перенос, удаление
  возвратом в ящик и повторный Play. Canvas проверен при изменении размеров.
- Собранный HTML проверен на отсутствие внешних модулей/стилей и корректность
  JavaScript; сборка из тех же исходников даёт одинаковые байты.
- Прямое открытие `file://` недоступно в управляемом браузере, поэтому оно
  не считается пройденной ручной проверкой. Физический смартфон не проверен;
  синтетические touch-события не заменяют проверку удобства на устройстве.

## Публикация

`release.json` содержит исходный HTML, JS и CSS. Сборщик читает все модули
из соответствующего тега, встраивает их в HTML и не использует изменённую
рабочую копию. `0.1.0` без поля `bundle` продолжает копироваться байт в байт.
Общий номер продукта хранится только в `VERSION`; перед новым выпуском
обновить его и changelog в отдельном изменении по задаче. Публикация #2
не меняет уже опубликованный тег и не создаёт новый тег автоматически.
