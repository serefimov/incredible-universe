# Аудит Spike #0.3 — задача #1

**Дата:** 2026-10-02. **Issue:** [#1](https://github.com/serefimov/incredible-universe/issues/1). **Ветка:** `1-init`.

Цель — сохранить исходную точку и отделить поведение реально написанного прототипа от требований MVP. В рамках расширенного владельцем #1 также добавлены README, GPL-3.0-or-later, gitignore, editorconfig, gitattributes и порядок работы с ветками/коммитами. Стек новой игры не выбран и новые зависимости не введены.

## Как проверялось

1. Сверка оригинального кода: численные параметры, фабрики состояния, гравитация, интегратор, события ввода, камера и отрисовка.
2. Воспроизводимая проверка **самого скрипта из HTML**, выполняемого в Node.js VM с имитацией DOM и управляемыми кадрами. Временные точки доступа добавляются только к строке скрипта в памяти; исходный файл не изменяется. Физика в проверку не переписана отдельной реализацией.
3. Визуальная проверка в браузере Codex: локальный HTTP, портретный viewport 390×844, реальное перетаскивание мышью и кнопки интерфейса.

Команда для повторения численных и входных проверок (Node.js 20+; пакеты не нужны):

```sh
node tools/audit-spike.mjs
```

**Результат:** 18 проверок прошли. Проверки, помеченные `known limitation`, подтверждают наличие исторических ограничений, а не их исправление.

**Пределы проверки:** события `pointerType: 'touch'` и pinch воспроизведены в имитации DOM, а не на физическом смартфоне. Такой прогон не проверяет системную отмену жестов, реальную точность касания, производительность устройства или поведение Safari/Chrome на телефоне. Реальный touch-first цикл должен быть подтверждён при мобильной проверке [#14](https://github.com/serefimov/incredible-universe/issues/14). Эмуляция размера экрана не считается проверкой физического устройства.

## Результаты численных и входных проверок

| Проверка | Результат |
| --- | --- |
| Начальная сцена | Подтверждены координаты, скорости, радиусы, неподвижность звёзд и подвижность планет |
| Полный цикл с событиями мыши и touch | Добавление → Play → Reset → перенос → повторный запуск → Reset → удаление → запуск без тела; сохранение конфигурации и обнуление времени/следа подтверждены |
| Одна единица каждого типа | Второе тело того же типа не выдаётся; удаление освобождает карточку |
| Некорректный перенос | Расстановка откатывается; расстояния 90 и `r1+r2+12` на равенстве допустимы |
| Блокировка в полёте | Добавление/перенос, pan и wheel не меняют конфигурацию/камеру вручную |
| Pan, pinch, колесо | Изменение камеры, удвоение масштаба при удвоении расстояния, пределы 0.22 и 2.8 подтверждены |
| Столкновение | Строгое пересечение останавливает; точное касание — нет; статус сохраняется, Reset разблокирует Play |
| Быстрое пересечение | Корабль с синтетической `vx = 80000` пересекает Солнце за шаг 0.0025 и не сталкивается по конечной позиции |
| Интегратор | Подтверждено обновление скорости перед координатой; корабль не влияет на тела |
| Совпадение координат | Смягчённое ускорение конечно |
| 60 / 120 Гц | В исходной сцене при `t ≈ 1.25` позиции расходятся примерно на `0.0030303834` мировых единицы; независимости от кадров нет |
| Длинный кадр | Реальная задержка 1 с даёт только 0.125 игрового времени; избыток отброшен |
| Исходная сцена без добавленных тел | При контролируемых кадрах 60 Гц корабль сталкивается с Бореей при `t ≈ 1.59833333`; это наблюдение, не условие будущего уровня |
| Отмена существующего drag | `pointercancel` подтверждает допустимый перенос |
| Отмена нового drag | Отменённый перенос остаётся активным; Reset его не очищает |
| Mouse hover | `pointermove` без `pointerdown` добавляет запись в карту указателей |
| Старт на узком экране | Корабль вне кадра; кнопка follow центрирует его |
| Редактирование после столкновения | Доступно без предварительного Reset; подтверждённое добавление само сбрасывает опыт |

Числа расписания кадров относятся к управляемому прогону скрипта. Браузерное расписание кадров не записывалось; его траектории не объявлены побитно идентичными этому прогону.

## Визуальная проверка браузером

Проверены исходная сцена, карточки ящика и предпросмотр, размещение и перестановка планеты, Play и follow, столкновение с Бореей, сохранение следа, Reset с сохранением тела, повторный полёт, перенос обратно в ящик и запуск без него. Проверены pan и переключение follow; чтение состояния карточек подтверждает выдачу/возврат тела.

На 390×844 стартовый корабль скрыт за левым краем; нажатие «Корабль» делает его доступным. Заголовок сокращается, ящик прокручивается горизонтально. Наличие элементов в таком viewport не подтверждает удобство управления пальцем.

Выявлено рассогласование bitmap canvas и размеров области при изменении viewport без обновления страницы: размеры снимаются один раз. Перезагрузка при уже установленном viewport восстанавливает соответствие. Это объясняет, почему выбор тела может не совпадать с видимым центром после изменения размера; проблема оставлена в исходнике.
